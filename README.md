# Heartquest
ハートクエストは、ゲームの中でキャラクターの気分を回復させる選択（散歩に行く、美味しいものを食べる、温泉に入る...）をしながら、実はその選択を現実の自分の行動記録として蓄積していくアプリです。  行動した後の感想を記録し、それを統計的に分析することで、「自分にとって何が本当に効くメンタルケアなのか」をデータで見つけ出すことを目指しています。

# ハートクエスト — ハッカソン計画書
## 作品タイトル
**ハートクエスト**
---

## 概要

自分を反映させたキャラのメンタルを回復させるゲーム。

- 散歩に行く、美味しいものを食べる、温泉に入るなどの選択肢を選んでもらい、ゲームキャラの気分バーのようなものを回復させる。
- その傾向をデータとして保存しておき、自分でもリアルで実行してみる。
- 実行した感想のフィードバックを打ち込み、それをデータとして解析し、自分のメンタル回復方法を見つけるものである。
- 蓄積したログを**統計的に分析**し、プレイヤーがどんな選択をしやすいかを可視化する。
- プレイヤーが求めれば、これまでの選択傾向から**リアルで行う行動を提案**する機能を持つ。

---

## ストーリー

### 思いついた背景や解決したいこと、想い

- 自分が落ち込んでいる時、どうしたら回復できるのかわからなかった。
- ゲームにすることで、自分を客観的に見ることができ、判断がしやすいのではないかと考えた。

### これを実現して、どんな世界を目指したいか

- メンタルの不調が生活に影響を及ぼすような状況を減らしたい。
- 「なんとなく」ではなく、自分のデータに基づいて「自分に合う回復方法」を見つけられる世界を目指す。

---

## 今回の差別化ポイント

1. **統計による傾向分析**
   選択ログと気分の変化量を統計的に処理し、「自分にとって何が効くのか」を数値で示す。感覚ではなくデータに基づいた自己理解を提供する。

2. **統計 × LLM のハイブリッド提案機能**
   プレイヤーが求めたときに、統計モデルが「気分改善の期待値が最も高い行動」を算出し、Claude API がその根拠を踏まえた自然な提案文を生成する。単なるLLM任せではなく、**説明可能な提案**にする。

3. **ローカル完結のプライバシー設計**
   メンタルヘルスに関わる個人データを扱うため、ログの保存・統計処理は手元のRaspberry Piサーバー内で完結させる。外部クラウドに送るのはLLMへの要約データのみ。

## システム構成/アーキテクチャ

| レイヤー | 技術 | 役割 |
|---|---|---|
| フロントエンド | React（PWA） | キャラ表示、気分バー、選択肢UI、感想入力 |
| バックエンド | Raspberry Pi + Flask/FastAPI + SQLite | ログの受信・保存、APIサーバー |
| 統計分析 | Python（pandas / numpy） | 行動カテゴリ別の平均・分散・頻度分布の算出、相関分析 |
| 提案生成 | Claude API | 統計結果を根拠に、自然文の提案・フィードバックを生成 |

### データの流れ

1. プレイヤーが選択肢を選び、実行後の感想を入力
2. フロントエンドからRaspberry Piサーバー（Flask + SQLite）へ送信・保存
3. 統計分析モジュールが行動カテゴリごとの気分変化を集計
4. プレイヤーが提案を求めた場合、統計結果をClaude APIに渡し、根拠付きの提案文を生成
5. 結果をフィードバックとしてプレイヤーに表示

### 統計機能の設計（段階的に実装）

- **Lv.1（必須・確実に動く）**：行動カテゴリ別の気分変化量の平均・分散、選択の頻度分布
- **Lv.2（時間があれば）**：時間帯・曜日・直前の気分スコアと選択行動の相関分析
- **Lv.3（発展）**：サンプル数が少ない場合でも安定した推定を出すための信頼区間つき平均（提案機能の根拠として活用）

### Raspberry Piの役割（今回の方針）

センサーなどのハードウェア拡張は行わず、**これまで使い慣れたUbuntuサーバーとしての運用に徹する**。API・DB・統計処理をすべてPi上で完結させ、実装の確実性とプライバシー面のストーリー性を両立させる。

---

## デモ運用上の注意点（重要）

統計・提案機能は、ある程度データが蓄積して初めて意味のある結果が出る。本番2日間だけのログでは説明力が乏しいため、以下を事前に準備する。

- 事前開発期間中、チーム2人が実際にアプリを使ってログを記録し続け、本物のデータを蓄積しておく
- 現実的なパターンを持つ合成データをバックアップとして用意し、ライブでの記録が不十分でもデモが成立するようにする
